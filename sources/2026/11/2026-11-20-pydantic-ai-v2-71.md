## Summary

Pydantic AI 2.71.0 adds a set of ready-made harness capabilities for long-running
agents, rule-based permissions for tools and shell commands, a `Goal` that keeps
unattended runs going until a check passes, and a `ToolBridge` that keeps large tool
sets cache-friendly. The release title is dated 2026-11-18; the feed entry appeared on
2026-11-19.

## Key points

- **Harness capabilities:** `ReportToolErrors`, `WrapUpAtLimits`,
  `ReportRemainingBudget`, `RequireVerification`, `ReportStaleFiles`, `CurrentTime`,
  `LabelCrossModelHistory` and `DenyUnanswered`, added to an agent instead of being
  hand-written into prompts.
- **`PermissionRule`:** allow, ask about, or deny tool calls and shell commands by
  rule, similar to coding-agent permission settings.
- **`Goal`:** keeps an unattended run going until a caller-defined completion check
  passes.
- **`ToolBridge`:** exposes `tool_search`, `tool_describe` and `tool_call` in place of
  the full tool list, so the prompt cache survives large or changing tool sets.
- `Shell(secret_env=...)` masks injected secrets in tool output; `ModelRouter` routes
  runs between models; `GoogleModel` supports `gemini-4-neon`.
- **Breaking:** `PeerNetwork` is renamed `PeerConnection`. StackOne's `api_key` is
  deprecated in favour of `auth`.
- Upgrade: `pip install -U pydantic-ai`.

## Why it matters

These are the building blocks of a coding-agent-style harness (permissions, goals,
budget awareness, verification) offered as library pieces, so custom agents can get
the same safeguards without reimplementing them.
