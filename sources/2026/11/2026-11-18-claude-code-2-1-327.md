## Summary

Claude Code 2.1.327 (2026-11-17) adds a safer way to add MCP servers with secrets, a
`/status` health list for broken configuration, and a long list of fixes, several of
which stop data loss (Remote Control deleting `.env` files, `/export` overwriting files,
`claude mcp add` wiping keys from `.mcp.json`).

## Key points

- **MCP secrets off the command line:** `claude mcp add-json <name> -` reads the server
  JSON from stdin, so a token does not end up in shell history (run it from a terminal,
  not inside a session).
- **Config health check:** `/status` now lists broken agent, skill, command, and output
  style files, keybinding errors, an unavailable sandbox, ignored permission settings,
  and hook matchers that never match. `/config` notes when other settings override a row.
- **Safety:** `/install-github-app` asks before changing a repo; `/export` asks before
  overwriting; Remote Control in worktree mode no longer deletes a running session's
  git-ignored files; project-scope `claude mcp add/remove` keeps other `.mcp.json` keys;
  an approved command no longer runs after Stop in cloud and runner sessions.
- **Other:** `/tui classic` names the non-fullscreen renderer; `attributionProject`
  names a billing group on Claude apps gateways; fixes for `--agents` and plugin agents
  being lost, compaction dropping a tool call, `claude -p` hanging on a stalled proxy
  (now times out after 10 s), and bare `host:port` proxies in non-terminal runs.
- Update with `claude update`.

## Why it matters

Running `/status` after editing skills, agents, or hooks now shows silent failures,
such as a hook matcher that never fires. The `.env` and `.mcp.json` fixes are worth the
update on their own.
