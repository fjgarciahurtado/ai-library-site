## Summary

Shirudo is an open-source Linux runtime from OpenAI and Cisco. It applies temporary
"shields" to running systems while a proper patch is prepared. A shield is a small eBPF
program that watches or blocks a specific behaviour. An operator can monitor it, approve
it, and deploy it without restarting the target. OpenAI shows Codex writing such
shields.

## Key points

- **How it works:** eBPF programs attach at kernel points to observe activity and apply
  targeted blocks. A shield can run in monitor mode before it enforces anything.
- **Integrity:** shields are signed and verified before loading, and the eBPF verifier
  and kernel controls still apply. A TPM keeps a verifiable record of shields being
  loaded or removed.
- **Demo:** in a controlled test, a shield generated by Codex added an input check to
  Java's Base64 decoder in a running Elasticsearch process. It blocked an exploit
  attempt without a restart.
- **Licence:** BSD 2-Clause; the BPF programs are dual-licensed BSD and GPL.
  Code: <https://github.com/shirudo-dev/shirudo>. Docs and a VM quickstart:
  <https://docs.shirudo.dev/>.
- A technical webinar is scheduled for 2026-12-15.

## Why it matters

This uses coding agents for defence: models write narrow, reviewable runtime mitigations
in the gap between a disclosed vulnerability and a deployed patch. The safeguards are
monitor mode, signing, and a human approval step.
