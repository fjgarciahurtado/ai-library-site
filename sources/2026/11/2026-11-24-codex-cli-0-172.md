## Summary

Codex CLI 0.172.0 makes optional MCP servers start only when first used, adds per-tool
approval for connected app tools, and adds Tab completion for slash-command arguments.
`codex exec resume` now restores the saved sandbox and workspace settings.

## Key points

- **Lazy MCP servers:** optional stdio MCP servers with cached tool lists now start on
  their first tool call by default. Sessions start faster and idle servers cost nothing.
- **Per-tool approval:** you can choose an approval reviewer per tool for connected app
  tools in `config.toml`.
- **Tab completion:** slash-command arguments complete with Tab (for example `/mcp lo`
  becomes `/mcp login`).
- **Agent command center:** Shift+Up and Shift+Down jump between task groups.
- **Resume in scripts:** `codex exec resume` restores the saved sandbox permissions,
  working directory, and workspace roots, so a resumed headless run behaves like the
  original.
- **Amazon Bedrock:** app-server clients can choose Bedrock Runtime during setup or sign-in.
- Code Mode now uses gRPC for all host connections. The `code_mode_host_grpc` setting is
  deprecated.
- Install or update: `npm install -g @openai/codex` (or `brew upgrade codex`).

## Why it matters

Lazy start for optional MCP servers is the same idea as Claude Code's deferred tool
loading: many MCP servers can be configured without slowing every session.
