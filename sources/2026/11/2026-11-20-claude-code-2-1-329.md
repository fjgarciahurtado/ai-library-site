## Summary

Claude Code 2.1.329 makes background work easier to see and stop: `/tasks` now lists
scheduled tasks, `/loop` wakeups, the goal, and forks. It also shows why a remote MCP
server refused a connection, warns where a folder's hooks come from, and lets Code Mode
run with OpenTelemetry on. `/code-review` with no target now reviews the whole branch.
The changelog gives no date; it was read on 2026-11-20 and is assumed to be from
2026-11-19.

## Key points

- **One place for background work:** `/tasks` lists this session's scheduled tasks,
  `/loop` wakeups, the current goal, and conversation forks. Select one and press `x`
  to stop it (asks for confirmation). "Exit and stop tasks" now ends scheduled tasks so
  they do not run again on resume.
- **Scheduled tasks need re-creating:** in new signed-in sessions, most tasks saved by
  earlier versions must be scheduled again. `--resume` of the session that created them
  still runs them.
- **Branch-wide review:** `/code-review` with no target reviews the whole branch against
  the default branch on most models (before, the current diff). With a PR number or URL
  it now stops instead of reviewing when `gh pr diff` fails.
- **MCP debugging:** each server's page in `/mcp` has a "Server message" row with the
  JSON-RPC error a remote HTTP server returned when it refused the connection.
- **Hook safety:** the folder trust dialog says where that folder's hooks are declared;
  non-interactive hosts such as Claude Desktop warn when managed-settings hooks fail to
  load.
- **Code Mode changes:** it now runs with OpenTelemetry events and metrics enabled (each
  tool call from a script emits its own events; tracing still disables it), and starts
  even when telemetry or feature flags are off. A PreToolUse hook that errors no longer
  blocks a script's tool call; set `"onFailure": "block"` on the hook to keep the old
  fail-closed behaviour.
- `/status` shows a "Marketplace auto-update" row naming managed marketplaces that do
  not auto-update, and why.
- Update with `claude update`.

## Why it matters

If you rely on a PreToolUse hook to refuse tool calls inside Code Mode scripts, add
`"onFailure": "block"` now, or a crashing hook will let the call through. Anyone using
`/loop` or scheduled tasks should check `/tasks` after updating and re-create tasks.
