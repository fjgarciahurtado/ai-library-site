## Summary

Claude Code 2.1.326 (2026-11-16) is mainly a fix release. Its one notable new ability is
that Code Mode now works together with agent teams. It also adds clearer warnings for
mistakes in tool rule flags, plugin manifests, and settings files, and fixes several
permission, sign-in, `/rewind`, and resumed-session bugs.

## Key points

- **Code Mode with agent teams:** you can now turn on Code Mode while agent teams are
  enabled. If you had already turned Code Mode on
  (`CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1`), sessions with teams now start in Code Mode.
- **Better warnings:** a startup warning when an `--allowedTools`, `--disallowedTools`,
  or `--tools` entry does not look like a complete rule; a note in `/plugin` and
  `claude plugin list` when a malformed `plugin.json` field is ignored; a warning naming
  a settings file saved with an error mid-session (before, it was skipped silently);
  a terminal warning when rules added in `/permissions` could not be saved.
- **Visibility:** `/status` shows when your provider or a variable such as
  `DISABLE_TELEMETRY` turns features off; Ctrl+O shows hidden startup notices and up to
  10,000 characters of a crashed hook's output; `OTEL_RESOURCE_INCLUDE_HOST` adds
  `host.name` and `host.id` to OpenTelemetry attributes (off by default).
- **Permission and safety fixes:** destructive Bash commands (`find -delete`,
  `cat a > b`, `sort -o`) are no longer summed up in the transcript as a search or read;
  `claude purge` now shows its prompts even with stdout redirected (one unseen Enter
  could delete a project's data); managed PreToolUse hook refusals now appear in
  OpenTelemetry; Up then Enter no longer answers Yes at a nested folder trust prompt.
- **Reliability:** `/rewind` is more accurate ("Code changes unknown" when a shell command
  changed files it cannot restore), resumed sessions keep their history after a crash or
  low memory, and requests over a model's `max_tokens` limit retry with the maximum the
  API reports. Update with `claude update`.

## Why it matters

Code Mode and agent teams were mutually exclusive until now, so anyone testing Code Mode
can use it in team sessions. The rest makes misconfiguration visible instead of silent,
which matters most for managed and unattended setups.
