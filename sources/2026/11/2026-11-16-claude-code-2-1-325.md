## Summary

Claude Code 2.1.325 (2026-11-13; there was no public 2.1.324) is mostly fixes, but it
changes several permission defaults. Sandboxed Bash commands no longer run without a
prompt by default, scheduled tasks and `/loop` ask before running skills that declare
tools or hooks, and read-only git commands in untrusted repositories now ask first. It
also closes more permission and sandbox gaps, and fixes many MCP task and Code Mode bugs.

## Key points

- **Sandbox no longer means "no prompt":** sandboxed Bash commands now go through the
  normal permission flow. To keep the old behaviour, set
  `sandbox.autoAllowBashIfSandboxed: true` (in the highest-ranking managed source if the
  sandbox is turned on by managed settings).
- **Unattended runs:** scheduled tasks and `/loop` now ask before running a skill that
  declares `allowed-tools` or hooks. Add `Skill(name)` to `permissions.allow` to let such
  a skill run unattended. "Always allow" in Desktop, IDE, and SDK hosts now saves a rule
  only when that rule would actually allow the command again, so scheduled tasks that
  relied on one may now wait for a person.
- **Git outside the project:** read-only git commands in a repository that is neither the
  project nor trusted now ask first; use `--add-dir` (not `additionalDirectories`) to
  allow them.
- **Security fixes:** a zstd decoding issue; compound Bash commands that could run without
  asking; a Bash allow rule that could run a different program than the one named;
  relative deny rules such as `Read(./.env)` that stopped applying after `cd`; deny rules
  for `mcp__plugin_*_` tools missed with a different letter case; gaps in sandbox
  protection of worktree settings, hooks, and a linked worktree's git folder. The
  sandbox now refuses writes to `.claude` settings, skills, agents, commands, and hooks
  in added directories too.
- **Plugins:** plugin loading skips unsafe paths and links (and `claude plugin validate`
  reports them); `.mcpb`/`.dxt` bundles unpack under the plugins directory; the install
  warnings now say plugins can run code with access to your files and shell;
  marketplace `ref` accepts any full commit ID (older clients cannot clone such pins).
- **MCP tasks:** Esc on a background MCP task's question now means "answer later" (it
  stays in `/tasks`), Claude is told when a task waits for your answer, and several
  stuck-task and reconnect bugs are fixed.
- **Other:** subagents cut off at the output limit are asked for a shorter full answer;
  `CLAUDE_CODE_MAX_CONTEXT_TOKENS` also sets the window for unrecognised `claude-*` model
  IDs; VS Code gets prompt suggestions (Tab accepts; `promptSuggestionEnabled: false`
  turns them off). Update with `claude update`.

## Why it matters

Anyone who relied on the sandbox to skip Bash prompts, or who runs skills from scheduled
tasks or `/loop`, will see new prompts after updating and should set the two options
above deliberately. The fixes continue the steady closing of permission-rule gaps.
