## Summary

Claude Code 2.1.328 brings auto mode to Opus 4.6 and Sonnet 4.6 on cloud providers,
lets MCP-tool hooks fail closed, and adds a batch of self-hosted runner options. It also
fixes two ways of losing saved scheduled tasks and a zsh bug that broke commands
containing words that start with `=`. The changelog gives no date; the release was read
on 2026-11-19 and is assumed to be from 2026-11-18.

## Key points

- **Auto mode on more platforms:** available for Opus 4.6 and Sonnet 4.6 on Amazon
  Bedrock, Google Cloud's Agent Platform, Microsoft Foundry, and the Claude apps gateway.
  Interactive sessions with no permission mode set now start in auto mode there.
- **Fail-closed MCP hooks:** set `"onFailure": "block"` on an `mcp_tool` hook (as
  already possible for command and HTTP hooks), and the action is blocked when the hook
  call itself fails. Use it for policy or audit hooks that must never be skipped silently.
- **Telemetry check:** `/status` and `claude doctor` warn when an OpenTelemetry exporter
  has no endpoint, so its data would be lost.
- **Headless safety:** `CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME` stops
  `claude -p --resume` / `--continue` from running a tool call that a hook had deferred.
- **Self-hosted runners:** `--repository-folder`, `--hook-label` for the orchestrator,
  `--metadata key=value` on `claude --environment` (labels for the `spawn-runner` hook),
  and two new orchestrator metrics on `/metrics`.
- **Fixes worth the update:** saving a scheduled task no longer erases the project's
  other tasks when the tasks file is unreadable, a typo no longer deletes a task, and
  zsh commands such as `echo ====` or `[ a == b ]` work again.
- Update with `claude update`.

## Why it matters

If you guard tools with MCP-based hooks, `"onFailure": "block"` closes the gap where a
crashed hook let the action through. zsh users who saw odd "not found" errors in Bash
commands should update.
